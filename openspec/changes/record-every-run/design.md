## Goals / Non-Goals

**Goals:**

- One record kind, written by every command of an edition's build chain, carrying what R2b needs to retire each existing record and check (the table under decision 3).
- The chain's commands declared once, as data, with their inputs and outputs; edges and order derived.
- `filmkit plan --json`: each node's freshness, measured host class, last seconds and readiness, without running or writing anything, for ETHOS's admission [S1, §5.3, §5.4; S5, rules 2, 3 and 7].
- `filmkit verify`: content binding wherever a record is cited, before a review round and a release.
- No change for films: nothing they declare, run, commit or receive.

**Non-Goals:**

- **Retiring anything (R2b).** `preflight`, `admitted`, `durations`, `set-aside`, `adoption`, `produce`, `tools`, the verifier's re-asks and every existing record stay, each still the authority its specification names.
- **Running the graph (R2b).** No `filmkit build`; the plan orders and judges, the films' task chains still run the commands.
- **Outputs keyed by their inputs (R2b).** Outputs stay at today's places and are overwritten as today.
- **Findings and exceptions in the run record (R2b, R3).** They stay in the owners' records, which the run record binds by digest (decision 3); the one exception model is R3's [S1, §5.7].
- **Per-thought narration freshness (R4).** The lock binds each take; until then the narration is one node per edition (decision 8).

## Decisions

### 1. The nodes are today's chain commands

- **Rests on:** the derivation's target nodes (`check`, `takes`, `sound`, `audit`, `picture`, `package`, `entry`, `verify`) each span several of today's commands [S1, §5.1]: `sound` is `select`, `assemble`, `refresh-captions` and `check-sound`, four processes run one after another by the film's tasks. A record is written by one run; four runs cannot write one record without one of them asserting what the others read.
- **Options:** (a) today's commands as nodes, the table a bridge that R2b replaces with the target's nodes; (b) the target's nodes now, each record written by the last command of its group; (c) every command that writes a duration record.
- **Chosen because:** (a). (b) makes one command assert inputs another command read. (c) would make nodes of commands that derive nothing: the convergence writes the cast, a tracked source (decision 8); `fit` reports variants; `admitted` reads receipts; `repair-pictures` redoes other nodes' work, and runs as those nodes (decision 5); the verifier and the reproduction judge the whole build. The record kind and the core do not change when R2b swaps the table, which is the derivation's own claim for a swap to doit [S1, §5].
- **Applies to:** the commands of the sample's chain (`.config/mise/config.toml:53-133`): `narrate`, `select`, `assemble`, `refresh-captions`, `check-sound`, `stage-picture` and `stage-picture-uncaptioned`, the geometry check and the cover check, `check-picture`, `render-draft`, `preflight`, `render-picture`, `render-picture-uncaptioned`, `validate-picture`, `validate-picture-uncaptioned`, `qualify-renderer`, `compare-pictures`, `package-metadata`, `package-film` and `scan-film`, each named as its duration record names it (`produce.py:212`, `tools.py:70,184-190`, `narrate.py:190-194`). A node is per edition, of the editions it applies to (decision 11); R2a has no film-wide node. The verifier (`verify`) and the reproduction (`reproduce`) are no nodes: each reads the whole build to judge it and derives nothing a later step reads, and R2b replaces both with `filmkit verify --technical-only` and `--release` [S1, §5.1.1]; they keep their duration records.
- **Reopened when:** R2b replaces the table.

### 2. One seam, one measurement

- **Rests on:** every chain command already measures itself in `durations.run`, which writes its duration record when the command ends, also when it is refused or fails (`durations.py:153-171`), and writes none with `record=False` (read-only runs) or when a signal ends the command where it stands [S6, build-time].
- **Options:** (a) `durations.run` opens the node's run at its start and closes it at its end, so the one `Run` measures both records; (b) a second wrapper at each of the six callers; (c) the run record replaces the duration record now.
- **Chosen because:** (a). (b) repeats the wrapper six times. (c) retires `durations`' record, which R2b does, and changes what the kit and `python -m filmkit.durations` read in a release meant to change nothing. Under (a) the duration record is derived from the same `Run` at the same moment, not kept beside it: started_at, seconds, load, phases and settings are equal in both files by construction, and a test holds them equal. The duration record is therefore no owner's record in decision 3's sense: it is the run's own measurement, written twice from one source until R2b retires it.
- **What the seam is told:** besides the command's name and `record`, the caller says whether the run is its node's whole run (`whole`, true by default). `produce` passes false for `stage-picture` with `--output`, `--duration`, `--start`, `--width` or `--height` (`produce.py:170-176`); `narrate` for `--ids` or the checks alone (`narrate.py:190-194`); `tools` where the arguments name other places than the node's (`tools.py:184-190`). A run that is not whole writes its duration record as today and, in place of the node's record, a partial record (decision 8). Two more things only the caller knows: `narrate` names its node (`node`), since its partial runs' duration records take other names (`narrate-checks`, `narrate-<ids>`); and `produce` names the way it was asked for (`way`), `native` for `render-picture --uncaptioned --native`, which the opening must know to state that way's inputs (decision 5). `produce` and `tools` leave with their one line, a `SystemExit`, inside the run, where they left outside it, so that the seam reads the line the command ends with; the duration record states the run as not completed either way. An owner that redoes a node's work inside another command opens that node's run through the seam's second entry, `durations.node(code, node)`, nested in its own run: it measures and writes the node's run record and no duration record, so the outer command's duration record still counts the seconds once (decision 5). The phases and settings that the work names stay with the outer command's run, whose duration record states them as before, so the node's record states its own seconds and load and no phases; the caller names its owner's refusals, which end the node's run as `refuse`, as the command's line would.
- **Imports:** `durations` imports `filmkit.graph` inside `run`, when a run opens, not at module level: the node table takes its lists from owners that import `durations` themselves (`picture/gates.py:54`, `picture/equivalence.py:54`, `delivery/packaging.py:45`, `picture/still_scan.py:61`), so a module-level import would close a cycle. `filmkit.graph` imports nothing of `durations`; the `Run` reaches it as an argument.
- **The seam never stops the command.** Opening or closing a node's run reads the node table and the files, and either can fail, as a damaged uncaptioned receipt made the opening raise before the command ran (the independent review of 24 November, S2). A failure of either is named in one line on standard error and the node's last record stands; the outputs the run writes then contradict that record, so the plan finds the node stale and `filmkit verify` refuses its bytes, and the command ends with its own line and writes its duration record as before. The table's one read of a receipt takes one that cannot be read as no derived picture's, as `uncaptioned_way` does, so that the plan and `filmkit verify` load the table and the owner's own check refuses the receipt.
- **Applies to:** the opening (inputs stated and hashed where their size or time differs from the node's last record), and the close (outputs hashed, record written by `repository.write`, `repository.py:114`, which replaces the file whole).
- **Reopened when:** R2b merges `durations` into the core.

In R2a each gate's findings and each declared exception stay in the owner's record, which every current reader (`preflight`, the verifier, the review round) still reads.
- **Options:** (a) the run record carries the derivation's whole field list now, findings copied from the owner's record; (b) it carries what the run itself knows and binds the owner's record as one of its outputs by digest; findings, exceptions and named results (such as the renderer's `drawn_sha256`, `picture/renderer.py:330`) move in with schema 2 in R2b, when the owner's record retires.
- **Chosen because:** (b). Under (a) each finding stands in two records until R2b. Under (b) nothing is stated twice, and R2b can still answer every question an owner's record answers: freshness from the run record's inputs, the answers from the bound record. The plan needs only the outcome, which is the run's own fact.

### 4. Each node's inputs are what its run reads, stated once, and a test holds them to the reads

- **Rests on:** where an owner binds its inputs, it keeps the list inline, sometimes twice: the sound gate's at `soundtrack/gates.py:71-75` and again at `preflight.py:202-206`; the picture gate's in `picture/gates.py:387-395` and again at `picture/rendering.py:405-411`; readiness at `preflight.py:290-313`; the equivalence at `picture/equivalence.py:119-130`; the stage at `picture/rendering.py:82-112`. Two owners already hold their list as paths: `delivery/packaging.py:281-293` (`film_inputs`) and `picture/still_scan.py:417-425` (`film_subjects`). The shared rules make one source a fact a hard requirement, and a check comparing two hand-kept copies no source [S5, Design principles]. Those lists also fall short of what the runs read: the sound gate reads the assembly record (`soundtrack/gates.py:70`) and the declared clarity floors through the declaration, and binds neither; the picture gate reads the declaration's wrapping, motion and detail exceptions (`picture/gates.py:16-35,58`) and does not bind the declaration; most other commands read the declaration (credits, caption terms, summary, file prefix, narration terms; after R1 `author` and `[pronunciation]`) [S7, C2].
- **Options:** (a) each owner's list becomes one function of paths in the owner's module, which its own record, its own check and the node all read, completed to what the run reads; (b) the node table states every list beside the owners', and a test holds them equal; (c) the owners read the node table.
- **Chosen because:** (a). (b) is the two hand-kept copies the rule forbids. (c) points the owners at a table R2b replaces. Where an owner binds no list (`select`, `assemble`, `refresh-captions`, the renders, the checks run through `tools`, `narrate`), the node table is the one statement. Where a list is completed, the owner's record gains the new keys and its bytes change once, which the release note names; its check then refuses what it let through before, such as a picture gate record that predates an edit of the declaration's exceptions. A film does nothing for it: its next build writes the records anew, as it does after any engine upgrade, since every such record binds the engine's version.
- **The whole declaration:** a node that reads any part of `content/film.toml` binds the whole file. That fails closed and makes every such node stale after any edit of the declaration, review policy included; the plan then overstates the work. Binding the parts each node reads would need a digest per table and a list of the tables each node reads, kept beside the code that reads them.
- **The test of what each run opens.** One recorder, owned by the engine and off unless `FILMKIT_OPENS` names a file, sees each process of a node's run, and a check compares what it saw with the node's declaration: a read outside the inputs of the node's way (a member of a declared folder counts) and a write outside its outputs fail, `build/runtime/` excepted (bounded work, and the tool cache that the pins bind). While a node's run is open, `durations` sets `FILMKIT_NODE` to the node and edition, which every child inherits.
  - **Python processes.** `filmkit/__init__.py` installs, when the variable is set, an audit hook (`sys.addaudithook`) that appends to that file each `open` below the film's root with its mode, each `os.rename`, which `os.replace` raises, and each `subprocess.Popen` with the paths below the root in its arguments and environment. A write through `repository.write` opens a `.partial` sibling and renames it over its target (`repository.py:92-111`); the check counts the rename's target as written and the sibling as no write. Every engine process imports `filmkit`, the narration's worker processes included, so every Python process of a run is seen; task 1.1 names any Python child that does not.
  - **Node processes.** When the variable is set, the engine starts Node (`tools.py:137`, `picture/renderer.py:215`) with `--permission-audit`, `--allow-fs-read` and `--allow-fs-write` set to the node's declared inputs and outputs, `build/runtime/`, the engine's package and the film's `node_modules`, and `--require` of an engine-owned recording module. In audit mode Node denies nothing and publishes each access outside those allowances on the `node:diagnostics_channel` channel `node:permission-model:fs` as `{permission, resource}`; the module subscribes to it and appends each to the same file with the process and `FILMKIT_NODE`, and the check fails those below the film's root. Network use, temporary folders and other paths outside the root are recorded and judged by nothing, so the run behaves as it does without the variable. Checked offline at the pinned Node 26.13.1 on 2026-11-23: `man node` describes `--permission-audit` so, and a read outside `--allow-fs-read` was published on that channel with `FileSystemRead` and the file's path while the script ran on. File access inside a native addon, such as the canvas package's, is not checked by the permission model; it reads the files its caller hands it, which Node's own reads name.
  - **Not seen.** FFmpeg, ffprobe, ExifTool, `mdimport` and Chrome are seen only through their arguments: each reads the files its command line, or for Chrome the page its Node driver hands it, names; the Python hook records a Popen's arguments, and the Node driver's own reads of the page it serves are recorded through the channel above. A concat list names files the same run wrote below `build/runtime/work/`. The nodes that run them (`render-picture[-uncaptioned]`, `render-draft`, `validate-picture[-uncaptioned]`, `qualify-renderer`, `compare-pictures`, `package-film` and `scan-film` for the media tools; the geometry check, the cover check and any other node that task 1.1 finds starting the browser, for Chrome) are named in the check's report with that limit.
  - The light suite runs the check for every node it can run on the sample's fixtures; the acceptance build (task 8.1) runs every node with the variable set, as the children of host tickets.
  - **What a run's declared inputs are, beside what the engine reads as it starts.** Every engine process reads some files as it starts. The film loader (`filmkit.film.read`) validates every file the declaration names: each edition's script, cast, pronunciation part and readings, the review prompt and the entry page (`film.py:742-810`, `declared_sources.py`); and the delivery format reads every edition's script as its module loads, for the chapter count that every script must state alike (`specification.py:19-38`). A command does this before its node's run opens, so nothing of it is recorded; a child, such as a narration worker, does it inside the run. The independent review of 24 November found those reads logged in children only, and failing the check of every narration. Options considered: (a) bind every file the engine reads as it starts as an input of every node; (b) name the start-up reads as an exemption that holds alike in every process; (c) narrow the loader and the modules so that a process reads only what its command uses. Chosen: (b). A node's declared inputs are the files from which its own code derives its outputs. What the engine reads as it starts derives nothing a node writes but film-wide values that the declaration, which every node binds whole, or the node's own sources also state: the film the loader returns is built from the declaration alone, and the files it validates only add problems, which refuse the command, so the run does not pass and its node is stale; the chapter count is refused unless every script states the same one, so an edition reads its own count in its own script. A node that derives from such a file reads it again in its own code, after start-up, and that read is judged. Under (a) an edit of the English pronunciation, or of the review prompt, makes every node of both editions stale, the renders and the films among them, and the plan asks for tickets for nothing; (c) changes when a command refuses, in a release that changes nothing for films. The recorder knows start-up by the stack: an engine module's body running as it is imported, or the code of `filmkit.film.read`; it logs those reads as `load`. The check lets a `load` through, as the exemption `start-up`, only for a file of the owner's list, `filmkit.film.start_up_files`: the declaration, each file it names or its editions derive (the scripts among them, which the chapter count reads) and each edition's readings. Any other read in a module's body, such as one in a module that a run imports late, is judged as a read; and a read at start-up through another path than the two the recorder knows is judged too, so the exemption fails closed by the file as well as by the code. The second review of 24 November found the stack alone let any file through.
  - **A file looked for and not found.** Python raises the `open` audit event before it tries the open, so a look for a file that does not stand would be logged as a read. The recorder logs an open for reading of a path that does not stand as a `probe`: the run read none of its bytes, though its outputs may follow from its absence. The check lets a probe through where the node would declare the path were it to stand: the table names an edition's readings as an input only where they stand (`nodes.stands`), and the check asks the table which places it would name if every such place stood. Any other probe fails, as a read would, naming the path as looked for.
  - **Limit: Node's allowances are wider than the check.** Node may read all of `build/runtime/` and the inputs of every way of its node, so a Node process's read of another node's stage below `build/runtime/work/`, or of the other way's inputs, is not published, where the Python half judges it (the review of 24 November, S3). Narrowing the allowances to the run's own way and to the work no node declares would need the way in every child, and would publish every file a render writes below `build/runtime/work/`, a volume not measured. Reopened when task 8.1's log is measured, or when R2b keys outputs by their inputs.
  - **Removals and renames.** `shutil.rmtree` names each member it removes through a folder's descriptor, relative to no working directory, and Python's events carry no descriptor for an open; the recorder logs the tree it removes as one removal, from rmtree's own event, and nothing of its walk. A rename's source that the same process did not write is a removal from its place, judged as a write; the `.partial` sibling of `repository.write` is no write. The review of 24 November found the members logged at the film's root and a rename that moved another node's file away never judged (S4).
  - **The recorder's own reads.** The seam and the recorder read files themselves inside a run: the node's last record, the node table's places, and the uncaptioned receipt that decides the way of a node that compares or packages the pictures (`chain.derived_uncaptioned`), which `node_options` reads each time a Node child starts. They read with the hook held quiet (`opens.quiet`), so the log holds the command's accesses alone; the review found the second edition's receipt logged as a read of the first edition's nodes for want of it.
  - **What the check lets through without a declaration.** Each is named in the check's report with the nodes it covered (`opens.EXEMPT`), never silently: `work`, the bounded work and tool copies below `build/runtime/` that no node declares, which this decision names; `environment`, a Python environment (a folder holding `pyvenv.cfg`, or that folder itself, as `VIRTUAL_ENV` names it in a child's environment) and the npm packages, which the lock files supply and the engine's pins bind; `records`, the run records and duration records, which the seam writes for the run itself and which no node derives from; `resolution`, the `package.json` files that Node's module resolution looks up beside each module it loads, whose contents the lock binds; `log`, the recorder's own log; `start-up`, the engine's reads as it starts, above; and each node's reads aside (`chain.ASIDE`), a read of a later node's output that, declared as an input, would close a cycle: `preflight` asks whether the earlier film package record would refuse the next packaging, and `package-metadata` states the films' sizes on the player page. A path outside the film's root is judged by nothing.
- **Applies to:** `soundtrack/gates.py`, `picture/gates.py`, `picture/rendering.py`, `preflight.py`, `picture/equivalence.py`, and the node table.
- **Reopened when:** R2b moves each list into its node, as the owners' records retire; or a measured plan shows the whole declaration's over-invalidation costing a ticket, after which the declaration is bound by its tables.

### 5. A file that several runs write is bound by its latest declared writer

- **Rests on:** today four kinds of run write a file that another run wrote, and the first draft's rule covered only the first [S7, C1]:
  - **A rewrite.** `assemble` writes the timeline and the assembly record (`soundtrack/assembly.py:633,644`), and `refresh-captions` reads both and writes them again with the selected narration (`captions/refresh.py:176-181`).
  - **A replacement.** Each edition's `package-metadata` writes the entry page `build/artifacts/film/index.html` whole without reading it: "Both editions' packages write this one page; each replaces it whole" (`delivery/packaging.py:87,142-167`).
  - **A redo.** `repair-pictures` moves a named picture and its receipt into an attempt, renders it again with `rendering.render_picture` or `derivation.render_uncaptioned`, and compares the pair again with `equivalence.compare_pictures` (`picture/repair.py:1-20,150-178`); a refused comparison names it as the next step (`picture/faults.py:89`).
  - **Two ways of one node.** `render-picture-uncaptioned` reads the captioned picture and its receipt when it derives and its own stage when it renders (`produce.py:94-102`, `picture/derivation.py:101-132`); the sample's Chinese chain renders with `--native` and its English chain derives (`.config/mise/config.toml:97-101`).
  - Task 1.1 found two writers more, each of a kind above. **A node that runs another node's owner:** `package-film` runs `package_metadata` twice, the second time with the films' sizes (`delivery/packaging.py:647,667`), so it replaces every output of `package-metadata` whole, the entry page among them; it is their `replaces` peer. **A search that runs a node's owner in its own process:** the convergence runs `select` (`narration/fitting.py:146`) and so writes the selected narration and alignment that `select` writes; it is a redo, as the repair's renders are.
  - The equivalence record has one writer, `compare-pictures`, at `picture/equivalence.py:512` or through `derivation.compare_derived` (`picture/derivation.py:512-544`), which `compare_pictures` calls (`equivalence.py:481`); the derived render writes none.
  - A node that reads and writes one path would be its own predecessor, which `graphlib` refuses as a cycle; and under a rule that compares every output with the file, the earlier writer's record, and `filmkit verify` with it, would refuse a normal build.
- **Options:** (a) the table declares every path that several nodes write and how each writes it; the latest declared writer's record binds the file's current bytes, and an earlier writer's binding of it holds through that record; a redo runs as the nodes it redoes; a node's ways are a setting it records; (b) merge the writers into one node (refused under decision 1); (c) leave a replaced output out of the earlier writer's record, so it binds nothing it wrote.
- **Chosen because:** (a). (c) would let a file that no declared writer wrote stand unnoticed. Under (a) every byte below `build/` that a record cites is bound by exactly one current record, and a change by anything else fails closed.
- **The writers of a path.** For each path written by more than one node, the table names each writer and its kind: `rewrites` (it reads the file and writes it again, after the writers it names) or `replaces` (it writes the file whole without reading it). The edges follow: a `rewrites` writer comes after the writers it names; a reader that writes nothing to the path comes after every writer of it but a rewriter that names the reader among the nodes it follows; `replaces` writers have no edge between them. A path that two nodes declare as outputs without such a declaration, and a cycle, refuse the table when it loads, naming the path or the nodes.
- **A reader that a rewriter follows.** `refresh-captions` rewrites the selected narration after `select` and after `assemble`, which reads it (`captions/refresh.py:181`, `soundtrack/assembly.py:153`). Options considered: (a) a reader comes after every writer, as the first revision said; (b) the rewriter names the reader among the nodes it follows, and the reader takes no edge from it; (c) the reader's read is declared as no input. Chosen: (b). Under (a) the sample's table has a cycle, `assemble:zh -> refresh-captions:zh -> assemble:zh`, which task 4.2 found when the table first loaded; (c) leaves unbound a file the assembly derives from. Under (b) the reader's binding of the path holds as an earlier writer's does: through the later record of the rewriter that follows it, whose recorded input of the path must equal the reader's recorded input; a change of the path by anything else leaves the reader stale.
- **Which record binds the file.** Among the declared writers' standing records, partial records included (decision 8), the one whose run ended last binds the path's current bytes; plan and `filmkit verify` compare the file with that record alone. Order is part of the binding, whatever the bytes: an earlier writer's binding holds only through a later run of a writer that comes after it in the declared order (`rewrites`, whose recorded input of the path must equal the earlier writer's recorded output) or of a `replaces` peer with no order between them, and only where that later run's own binding holds in turn, so that a chain of such runs reaches the latest record; a rewriter whose output a later writer replaced carries no binding, a reader's included. A run of a writer makes every writer declared after it stale, "its output replaced by an earlier writer's run", until that writer runs again; so `assemble` run again after `refresh-captions` leaves `refresh-captions` stale and `check-sound` behind and not ready, even where `assemble` writes the bytes it wrote before. `filmkit verify` lists such a writer and refuses nothing for it, since the latest record accounts for the bytes. Where the file's current bytes equal no standing record of a declared writer, the path is named as changed by no declared writer: its nodes are stale and `filmkit verify` refuses. So it is where a rewriter read, after an earlier writer's run that it follows, bytes that the earlier writer did not write and no declared writer's run between the two wrote: the bytes it carried forward were written by none, though the file now equals the rewriter's record. The independent review of 24 November found that case passed (an edit of the timeline between `assemble` and `refresh-captions`, verified with exit 0), and the rule now names it; `order` stays the reason only where an earlier writer ran again after the rewriter. A rewriter run again reads its own previous output, which no standing record states once its record is replaced; so when its run opens, the seam compares each path it rewrites with its own previous record, and where the bytes are the ones that run wrote, the new record states, beside the bytes it read, the digest its chain of runs first read from another writer (`carried`). The binding and the rule above read that digest too. The second review of that day found two caption edits, each refreshed, refused for want of it.
- **A redo runs as the nodes it redoes.** `repair-pictures` is no node (decision 1), but each render and comparison it runs opens the run of `render-picture`, `render-picture-uncaptioned` or `compare-pictures` through the seam, nested, with the same inputs and outputs (decision 2). Those records then bind the repaired pictures and the new comparison, so no record is left behind by the repair, and the durations sum counts the repair's seconds once, as today. The pictures it moves into its attempt are its own evidence, which no node declares. The convergence's `select` opens the run of `select` the same way, so the record of `select` binds the selection the search left.
- **Ways of one node.** A node whose inputs depend on how it runs declares each way's inputs and records its way among its settings: `render-picture-uncaptioned` records `derived` or `native` (`derivation.uncaptioned_way`, `produce.py:94-102`). Freshness reads the inputs of the recorded way; a node without a record takes the way that `uncaptioned_way` gives without `--native`. Its outputs are the same either way. The `derived` way begins by validating the captioned picture (`derivation.py:340`, `rendering.validate_picture`), so it reads every input of `validate-picture`, the captioned stage and the stage's sources among them; the review of 24 November found them missing, and a test now holds the one way to the other node's inputs.
- **Applies to:** the timeline and the assembly record (`rewrites` by `refresh-captions` after `assemble`) and the selected narration (`rewrites` by `refresh-captions` after `select` and `assemble`); the five caption documents (`replaces` by `assemble` and `refresh-captions`); the entry page and the viewing package's files (`replaces` by `package-metadata` and `package-film` of every edition); `repair-pictures` and the convergence's `select`; `render-picture-uncaptioned`; and any other path that task 1.1 finds with several writers, each declared before the table loads.
- **Reopened when:** R2b keys outputs by their inputs, after which no path has two writers; or task 1.1 finds a writer of a kind that is none of these.

### 6. Freshness: size and time first, the digest on change; `filmkit verify` hashes everything

- **Rests on:** the derivation's rule [S1, §5.1], adopted on the reader's finding 7 and its note [S2]: hashing every input and output at every plan costs seconds per edition of pictures and films, while doit's default and Git's index stat first and hash on change; the shortcut misses a change that keeps both size and time, so a full re-hash must run where digests are cited [S1, §5.1].
- **The rule:** a node is fresh when its record can be read and is of a schema the core reads, its outcome is `pass`, its engine version, `released.json` digest and pins equal the running engine's, its declared input names, for the way it recorded (decision 5), equal the record's, every input and output exists, and each has its recorded size and time or else, hashed again, its recorded digest, an output that several nodes write being judged by decision 5's rule. It is stale otherwise, with each reason named; it is behind when it is fresh and a node upstream is stale, failed or unrecorded. It is ready when every node upstream is fresh with outcome `pass` and every input it declares exists: host rule 2 queues a ticket only when the checks that take seconds have passed and the files its command reads exist [S5, rule 2].
- **The plan writes nothing.** An input whose time moved and whose digest held is hashed again at each plan until its node next runs. Options considered: refresh the record's times as the plan finds them, as Git refreshes its index; or keep them in a separate cache. Refused: a plan that rewrites a record can overwrite a record that a running node wrote between the plan's read and its write; a cache is a second store. The cost falls only on files touched without a change, such as after a checkout, which touches tracked sources of kilobytes [S1, §5.1].
- **`filmkit verify`** re-hashes every input and output of every standing record, a partial record included, writes nothing, and refuses, exiting 1, in two cases only: a file below `build/` whose bytes no record of a declared writer accounts for (decision 5), which is a writer the table does not know; and a node that size and time call fresh whose digests differ, which is the shortcut's blind spot. Each is named with its path and nodes. A node stale for a reason the plan already sees (an edited source, an upstream run since, a missing output such as one a set-aside moved) is listed and refuses nothing: in R2a no command refuses on staleness, and today's owners keep refusing what they refuse. It does not require a record for every node, so a build made before this release verifies as it did; R2b's `verify` requires them. A review round's preparation (`review/round.py:181`) and a release's record (`delivery/release.py:421-455`) run it first and refuse with its lines.
- **Reopened when:** task 8.3 measures a plan of a whole film's built tree above 2 s, or a hash of the changed files above the derivation's estimate of 0.1 to 0.3 s per 250 MB picture [S1, §5.1].

### 7. The host class is measured as host rule 3 measures it

- **Rests on:** host rule 3: a build is light only when its CPU time (user and system, every descendant) over its wall time is at most 2.0, and the summed `%cpu` of its process tree, sampled every five seconds by `ps`, has no two consecutive samples above 200 %; one that measures over two cores by either measure is heavy from then on; model work on the GPU is heavy whatever cores it uses [S5, rules 2 and 3]. The derivation adopts this for each node and expects the classes of its table [S1, §5.1].
- **The measures:** CPU time as `resource.getrusage` of the process and its waited-for children, at the run's two ends; samples from a daemon thread that reads `ps -A -o pid=,ppid=,%cpu=` every five seconds and sums the command's process tree. Both raw measures are recorded (`measured`: `cpu_seconds`, `cpu_per_wall`, the sample count and the longest run of samples above 200 %), with the class they give.
- **The class:** `gpu` where the node declares model work (`narrate`); else `heavy` where this run or the node's previous record measured heavy; else `light`. A node with no record is `unmeasured` in the plan, with its expected class from the table.
- **Options:** (a) the engine classifies with the rule's numbers as constants in `filmkit.graph.host`, citing the rule, and records the raw measures beside the class; (b) record the raw measures alone and leave the class to the caller.
- **Chosen because:** (a): the plan must state a class for ETHOS's admission [S1, §5.4], and the raw measures let any reader judge again. The engine takes no ticket and sends nothing to the keeper; the first measured run's reading is reported by the session that ran it [S5, rule 3].
- **Limit:** a node's heavy class lives in its record, so clearing `build/` forgets it; the node is then `unmeasured`, never `light`.
- **Reopened when:** ETHOS's host admission declares the thresholds in its own declaration, from which the engine then reads them; or `getrusage` misses descendants that a test finds (a grandchild not waited for by its parent).

### 8. The search is no node, and a run of part of a node writes a partial record

- **Rests on:** narration's convergence is a search that writes the cast's retakes, a tracked source [S1, §2.1]; a narration of chosen segments (`narrate --ids`) or of checks alone writes a duration record of another name (`narrate.py:190-194`); `stage-picture` with `--output`, `--duration`, `--start`, `--width` or `--height` writes another stage than the node's (`produce.py:170-176`).
- **Chosen because:** a record states that a node's outputs follow from its inputs; a run that covered part of the node, or wrote another place, cannot state that. Yet it writes the node's outputs, and decision 5 must account for every byte it wrote, or `filmkit verify` would refuse every build after a retake. Such a run writes its duration record as today and a partial record, `<node>.partial.json` beside the node's: the outputs as they stand after it, its outcome and its time, and no inputs. A partial record is a `replaces` writer (decision 5) of the outputs it states, so it accounts for their bytes, and it never makes the node fresh: where the outputs it states differ from those the node's record states, the plan reports the node stale, "changed by a partial run", until a whole run writes its record. A run that wrote only elsewhere, such as `stage-picture --output build/runtime/work/trial`, states the node's outputs unchanged and leaves the node as it was; the review of 24 November found such a run making the node and every node after it stale. The convergence's child narrations are whole runs and write the `narrate` record.
- **What a node writes besides its products.** A cache that a node reads and adds to is its output and not its input: the narration's alignment and transcript caches (`narration/alignment_records.py`, `narration/transcript_records.py`), which each narration reads where an entry stands for a recording and adds to where none does. A run reads them as they stood and leaves them grown, so as an input the folder as it stood at the run's start would differ at once from the folder the run left; as an output its members are bound as the run left them, a read of a node's own output is allowed, and an entry damaged afterwards makes the node stale and fails `filmkit verify`. A receipt that a node writes only when it fails is its output too: `package-film` writes `packaging-failure.json` when an encode fails and removes it when it passes (`delivery/packaging.py:90,491,665`), so the record of a refused run binds it and the record of a passing run states it absent. The review of 24 November found the three undeclared; the test of what each run opens now runs each owner's writing code under the recorder.
- **What other commands write:** a command that is no node and writes below `build/` (the convergence and judgment records, `fit`, `admitted`, the set-aside, the review round, the release, the repair's attempts) writes no file that a node declares as an output. A folder output names its members by pattern, so a file another command writes into that folder is no member; the convergence's record in the narration folder (`narration/converge.py:330`) is such a file. The test of what each run opens (decision 4) holds every such command's writes outside every node's declared outputs.
- **The occurrence plan.** The readings check writes `build/evidence/readings/<code>-plan.json` (`narration/readings.py:466`). A narration runs it in its gate before its run opens, in every scope, a dry run included (`narration/narrate.py:137-138,170-174`), and `python -m filmkit.narration.readings` runs it alone; no node reads the file, and a review round cites it by digest (`review/prompts.py:319`). Options considered: (a) an output of `narrate` that `filmkit verify` ignores after a dry run; (b) a partial record of `narrate` from a dry run; (c) no node's output. Chosen: (c). The file is written before the node's run opens, so (a) binds as the run's output bytes the run did not write and needs a case of its own in `verify`; under (b) a dry run, which writes no duration record and no take, would leave the narration stale for nothing. Under (c) no record cites the file, so neither the plan nor `verify` judges it, and the test of what each run opens sees no write of it inside a run.
- **Limit:** after a retake by `narrate --ids`, the plan reports the edition's narration stale until a whole narration runs, which reuses every received take by its fingerprint (`group_generation.py:156-174`); its last seconds then overstate that run.
- **Reopened when:** R4's lock binds each take and makes narration's freshness per thought; or a node reads the occurrence plan.

## Risks / Trade-offs

- [A record says fresh while a file changed with its size and time kept] → `filmkit verify` re-hashes before a round and a release (decision 6); the plan is advisory in R2a and no command refuses on it.
- [A build command's work slows by hashing] → inputs are hashed only where their size or time differs from the node's last record; outputs are hashed once each, which `film_bindings` and the renderer already do for most of them today. Task 8.2 measures the cost on the sample.
- [The `ps` sampler adds load] → one `ps` every five seconds, only for a run longer than five seconds.
- [The table falls behind a command] → a test names every command that writes a duration record and requires a node for it or its listed reason for none (decisions 1 and 8); the test of what each run opens refuses a read outside a node's inputs and a write outside its outputs, so a missing input or an undeclared writer among the nodes fails a test, not a build (decision 4).
- [A file changed by something outside the engine] → it matches no record of a declared writer, so its nodes are stale and `filmkit verify` refuses, naming it (decision 5).
- [Two records of one fact] → each duration record and run record come from one `Run` (decision 2); no owner's field is copied (decision 3).

## Migration Plan

Built in the engine on R1's head, released as 0.32.0.
